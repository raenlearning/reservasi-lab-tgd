# 2026-09-21

## Analisis migrasi ke Laravel + MySQL (permintaan penjelasan, belum eksekusi)

Pengguna melampirkan diagram arsitektur target: **Flutter (Mobile) → Laravel (API)
→ MySQL**, dengan Sanctum/JWT untuk auth. Ia ingin tahu alur kerja aplikasi
sekarang, arsitektur data, dan apakah migrasi penuh memungkinkan.

### Temuan dari kode (bukan asumsi)

- **7 query real-time** (`.snapshots()`) dan **9 StreamProvider** — kalender,
  daftar pengajuan, dasbor admin semuanya bergantung pada stream Firestore
- **Tidak ada penanganan offline sama sekali** — tidak ada `connectivity_plus`,
  tidak ada `Settings(persistenceEnabled:)`. Cache offline yang ada murni
  bawaan SDK Firestore
- **Transaksi Firestore gagal saat offline** (dikonfirmasi via pencarian:
  transaksi tidak dipersistenkan, tidak dijalankan offline). Karena pengajuan
  memakai `runTransaction`, **mengajukan reservasi tanpa internet akan gagal**
- Ukuran kode: core 2.591 + data 3.006 + features 6.839 = **12.436 baris**
  → **76% dipertahankan**, **24% (lapisan data) ditulis ulang**

### Kesimpulan utama

Migrasi **memungkinkan dan justru menyederhanakan**:

| Sekarang | Setelah |
|---|---|
| `slot_locks` + model + service + rules (±600 baris) | `DB::transaction` + `lockForUpdate()` |
| `mulai_menit`/`selesai_menit` kolom bantu | cukup `TIME` |
| Login NIM/NIDN via hack email internal | login langsung `nomor_identitas` |
| Notifikasi MATI (butuh Blaze) | FCM HTTP v1 dari Laravel — hidup |
| Upload berkas MATI (butuh Blaze) | `Storage::disk()` — hidup |

Yang dikorbankan: **real-time otomatis** dan **cache offline gratis** — harus
dibangun sendiri (polling/SSE/Reverb; sqflite).

### Kendala yang diidentifikasi (berurut risiko)

1. Real-time hilang — risiko tinggi. Rekomendasi: polling 15 detik dulu
2. Cache offline hilang — risiko sedang
3. Otorisasi pindah dari DB (rules) ke aplikasi (Policy) — risiko sedang, dampak besar
4. Zona waktu — set `APP_TIMEZONE=Asia/Jakarta` SEBELUM menulis data pertama
5. `lockForUpdate()` bergantung gap lock InnoDB — pastikan `INDEX (lab_id, tanggal, status)`
6. **Kata sandi TIDAK bisa dimigrasikan** — Firebase Auth tidak mengekspor hash.
   Semua pengguna harus reset. Ini yang paling sering terlewat.

### Berkas yang dibuat

- `docs/MIGRASI-LARAVEL-MYSQL.md` — 8 bagian: alur kerja sekarang, arsitektur
  data, komponen migrasi (tabel mana berubah/bertahan), kelayakan, 6 fase langkah,
  persiapan, 7 kendala, rekomendasi + daftar periksa sebelum potong
- `README.md` — tambah rujukan ke dokumen migrasi

### Prinsip yang direkomendasikan

Migrasi **berdampingan**, bukan potong sekaligus: tambahkan sakelar
`AppConfig.backend` (pola sama seperti `useCloudFunctionsForBooking` yang sudah
ada), jalankan kedua backend dengan data sama, bandingkan hasil, baru potong.
Firebase dipertahankan minimal 2 minggu sebagai jalan mundur.

**Belum ada kode migrasi yang ditulis** — pengguna meminta penjelasan dulu.

### Keputusan desain penting

**Semantik slot BERUBAH dari versi Firebase.** Dulu pengajuan `Menunggu` TIDAK
menahan slot (beberapa pemohon boleh mengajukan waktu sama). Sekarang
`Menunggu` **IKUT menahan** — satu slot, satu pengajuan aktif.

Alasan: ketentuan pengguna menyebut "422 bila slot bentrok", dan interpretasi
longgar membuat dua pengajuan pada jam sama sama-sama lolos 201. Sudah
diverifikasi ulang: uji 6 dan 7 semula GAGAL, lalu diperbaiki dan lulus.

Konsekuensi: kalender juga menampilkan `Menunggu` sebagai terpakai, supaya
pengguna tidak melihat slot "kosong" yang sebenarnya akan ditolak server.

### Uji yang dijalankan (15 skenario, semua lulus)

Login benar/salah, tanpa token, kalender, ajukan 201, slot sama 422, slot
bentrok 422, bersinggungan di batas 201, durasi >4jam 422, di luar jam 422,
tanggal lampau 422, mahasiswa verifikasi 403, tolak tanpa alasan 422, setujui
200, verifikasi ulang 403.

### Bug yang ditemukan & diperbaiki

1. `APP_FALLBACK_LOCALE=id` tanpa berkas terjemahan `id` → pesan validasi
   muncul sebagai kunci mentah `validation.after_or_equal`.
   Diperbaiki: fallback `en` + trait `PesanIndonesia`.
2. Semantik slot (di atas).
